## A. เป้าหมาย

จบบทนี้คุณจะ:

## C. แนวคิด

### C.1 อ่าน `ls -l` ให้ครบ

```text
-rwxr-xr--  1 mengkub devs  12345 Oct 28 02:43 server-start.sh
│└┬┘└┬┘└┬┘  │  │       │      │        │         └─ ชื่อไฟล์
│ │  │  │   │  │       │      │        └─ เวลาแก้ไขล่าสุด
│ │  │  │   │  │       │      └─ ขนาด (ไบต์)
│ │  │  │   │  └─ กลุ่มเจ้าของ
│ │  │  │   └─ เจ้าของ (user)
│ │  │  └─ จำนวน hard link
│ │  └─ สิทธิ์ของ "คนอื่น" (others)
│ └─ สิทธิ์ของ "กลุ่ม" (group)
└─ สิทธิ์ของเจ้าของ (user)
```

ตัวแรกหน้าสุด = ชนิดไฟล์: `-` ไฟล์ปกติ · `d` โฟลเดอร์ · `l` symlink

### C.2 สิทธิ์ 3 ระดับ × 3 สิทธิ์

| ตัวอักษร | ตัวเลข | ใช้กับไฟล์ | ใช้กับโฟลเดอร์ |
| --- | --- | --- | --- |
| `r` read | 4 | อ่านเนื้อหาได้ | **list** ดูรายชื่อไฟล์ได้ |
| `w` write | 2 | แก้ไข/เขียนทับได้ | สร้าง/ลบไฟล์ในโฟลเดอร์ได้ |
| `x` execute | 1 | รันเป็นโปรแกรมได้ | **เข้าไปได้** (cd) |

**สำคัญมาก:** โฟลเดอร์ที่ไม่มี `x` จะเข้าไม่ได้แม้มี `r` — และโฟลเดอร์ที่ไม่มี `r` จะ `ls` ไม่ได้แต่ยังเข้าได้ถ้ารู้ชื่อไฟล์ (นี่คือช่องโหว่ที่คนมักไม่รู้)

ตัวอย่างการแปลง:

```text
rwxr-xr-x  →  755
rw-r--r--  →  644
rwx------  →  700
rw-------  →  600
rwxrwx---  →  770
r-xr-xr-x  →  555
```

### C.3 `chmod` สองภาษา

```bash
chmod 755 script.sh        # ตัวเลข: เจ้าของ rwx, กลุ่ม r-x, อื่น r-x
chmod u+x script.sh        # ตัวอักษร: เพิ่ม x ให้เจ้าของ
chmod go-rwx secret.key    # ลบทุกสิทธิ์ของ group และ others
chmod -R u+rwX dir/        # X = ใส่ x เฉพาะโฟลเดอร์ (มีประโยชน์เวลาคัดลอกโครงสร้าง)
```

**ค่าที่ควรใช้เป็นมาตรฐานของโปรเจกต์เรา:**

| ชนิด | สิทธิ์ | เหตุผล |
| --- | --- | --- |
| โฟลเดอร์เซิร์ฟเวอร์ | `755` หรือ `750` | ต้องเข้าได้ แต่ไม่ให้คนอื่นเขียน |
| ไฟล์ `*.jar`, `*.properties` | `644` | อ่านได้ เขียนได้เฉพาะเจ้าของ |
| script ที่รันเอง (`*.sh`) | `755` | ต้อง execute ได้ |
| ไฟล์ที่มีรหัสผ่าน (`*.env`, `*.key`) | `600` | เจ้าของเท่านั้น |
| ไฟล์สำรองข้อมูล (`*.tar.gz`) | `600` | ข้อมูลผู้เล่น = ข้อมูลส่วนบุคคล |
| `logs/` | `750` | มี IP ผู้เล่น อย่าให้คนอื่นอ่าน |

> 🔐 **ทำไม log ต้องป้องกัน?** log มี IP address, UUID, ข้อความแชท — เป็นข้อมูลส่วนบุคคล ถ้ารั่วไหลอาจผิดกฎหมายคุ้มครองข้อมูล (PDPA)

### C.4 `chown` และ `chgrp`

```bash
sudo chown mengkub server.properties        # เปลี่ยนเจ้าของ
sudo chown mengkub:devs server.properties   # เปลี่ยนเจ้าของ + กลุ่ม
sudo chown -R mengkub:devs /srv/minecraft   # ทั้งโฟลเดอร์ (ระวัง! ใช้ -R ให้ถูกพาธ)
sudo chgrp devs plugins/                    # เปลี่ยนแค่กลุ่ม
```

> ⚠️ ก่อน `chown -R` ทุกครั้ง ให้ `pwd` และ `ls -d "$path"` ยืนยันก่อน — พิมพ์พาธผิดหนึ่งตัวอักษรอาจเปลี่ยนเจ้าของทั้งระบบ

### C.5 `umask` — สิทธิ์เริ่มต้นของไฟล์ใหม่

```bash
umask          # ดูค่า (ปกติ 022)
umask 027      # ตั้งใหม่: ไฟล์ใหม่ = 640, โฟลเดอร์ใหม่ = 750
```

สูตร: **สิทธิ์จริง = 777 − umask** สำหรับโฟลเดอร์ และ **666 − umask** สำหรับไฟล์

| umask | ไฟล์ใหม่ | โฟลเดอร์ใหม่ | ใช้เมื่อ |
| --- | --- | --- | --- |
| `022` | 644 | 755 | ค่าเริ่มต้นทั่วไป |
| `027` | 640 | 750 | เซิร์ฟเวอร์ที่มีข้อมูลผู้เล่น |
| `077` | 600 | 700 | ข้อมูลลับ |

ตั้งใน script ที่สร้างไฟล์ข้อมูลผู้เล่นทุกครั้ง:
```bash
umask 027
```

### C.6 ทำไมห้ามรันเซิร์ฟเวอร์ด้วย `root`

1. ถ้าปลั๊กอินมีช่องโหว่ (และมักมี) ผู้โจมตีจะได้สิทธิ์ **ทั้งเครื่อง** ไม่ใช่แค่เซิร์ฟเวอร์
2. ไฟล์ world ทั้งหมดจะกลายเป็นของ root → คุณจะแก้ไม่ได้โดยไม่ใช้ sudo
3. `rm -rf` ที่พลาดหนึ่งครั้ง = ลบทั้งระบบ

**แนวปฏิบัติ:** สร้างผู้ใช้เฉพาะ (`useradd -m -s /bin/bash minecraft`) แล้วรันเซิร์ฟเวอร์ด้วยผู้ใช้นั้น + ใช้ `systemd` จำกัดสิทธิ์ (Month 11)

## D. ลงมือทำ

### ขั้นที่ 1: ทดลองแปลงสิทธิ์

```bash
mkdir -p /tmp/perm-lab && cd /tmp/perm-lab
for p in 644 600 755 700 640 750; do
  echo "test" > "f$p.txt"
  chmod "$p" "f$p.txt"
done
ls -l
```

**จดผลจริงลงตารางใน `notes/permissions-lab.md`** — คอลัมน์: ตัวเลข | ตัวอักษรที่เห็น | ใครอ่านได้ | ใครเขียนได้ | ใครรันได้

### ขั้นที่ 2: ทดลองผลของ `x` บนโฟลเดอร์

```bash
mkdir -p /tmp/perm-lab/dir-rwx /tmp/perm-lab/dir-r-- /tmp/perm-lab/dir--x
echo hello > /tmp/perm-lab/dir-rwx/inside.txt
echo hello > /tmp/perm-lab/dir-r--/inside.txt
echo hello > /tmp/perm-lab/dir--x/inside.txt

chmod 700 /tmp/perm-lab/dir-rwx
chmod 400 /tmp/perm-lab/dir-r--
chmod 100 /tmp/perm-lab/dir--x

echo "--- ls dir-r-- (ควรได้) ---"; ls /tmp/perm-lab/dir-r-- 2>&1 | head -2
echo "--- cat dir-r--/inside.txt (ควรไม่ได้) ---"; cat /tmp/perm-lab/dir-r--/inside.txt 2>&1 | head -2
echo "--- cat dir--x/inside.txt (ควรได้ ถ้ารู้ชื่อไฟล์) ---"; cat /tmp/perm-lab/dir--x/inside.txt 2>&1 | head -2
```

**สังเกต:** `dir-r--` (400) `ls` ได้แต่ `cat` ไม่ได้ · `dir--x` (100) `ls` ไม่ได้แต่ `cat` ได้ — พิสูจน์ว่า `r` กับ `x` ของโฟลเดอร์ทำคนละหน้าที่

### ขั้นที่ 3: ทดลอง `umask`

```bash
cd /tmp/perm-lab
( umask 022; touch u022.txt; mkdir u022dir )
( umask 027; touch u027.txt; mkdir u027dir )
( umask 077; touch u077.txt; mkdir u077dir )
ls -ld u0*dir u0*.txt
```

จดผลจริง (คาดว่า `u022.txt` = 644, `u027.txt` = 640, `u077.txt` = 600)

### ขั้นที่ 4: ตั้งสิทธิ์ให้โครงสร้างเซิร์ฟเวอร์จริง

```bash
cd ~/minecraft-mmo-dev
umask 027

# โฟลเดอร์: เจ้าของ rwx, กลุ่ม r-x, คนอื่นไม่มีสิทธิ์
chmod 750 server scripts backups notes lab 2>/dev/null

# script: 755 (ต้องรันได้)
chmod 755 scripts/*.sh 2>/dev/null

# ไฟล์ข้อมูล: 640 (เจ้าของแก้ได้ กลุ่มอ่านได้)
find server -type f -name "*.properties" -exec chmod 640 {} \; 2>/dev/null
find server -type f -name "*.yml" -exec chmod 640 {} \; 2>/dev/null

# ไฟล์ลับ (ถ้ามี): 600
chmod 600 server/*.env 2>/dev/null

echo "--- ผลลัพธ์ ---"
ls -ld server scripts backups
ls -l scripts | head -5
```

### ขั้นที่ 5: ตรวจว่ามีไฟล์ที่ "ใครก็เขียนได้" หรือไม่

```bash
cd ~/minecraft-mmo-dev
```

## F. โค้ดตัวอย่าง — ตั้งสิทธิ์แบบปลอดภัยใน script

```bash
#!/usr/bin/env bash
# secure-permissions.sh — ตั้งสิทธิ์มาตรฐานให้โฟลเดอร์เซิร์ฟเวอร์ (Day 13)
set -uo pipefail

SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
source "${SCRIPT_DIR}/lib.sh"

BASE="${1:-$HOME/minecraft-mmo-dev}"
[[ -d "$BASE" ]] || die "ไม่พบโฟลเดอร์: $BASE" 2

umask 027

apply() {  # apply <สิทธิ์> <พาธ>
  local mode="$1" path="$2"
  [[ -e "$path" ]] || return 0
  chmod "$mode" "$path" && log "ตั้ง $mode : $path" || warn "ตั้งไม่ได้: $path"
}

for d in server scripts backups notes; do
  [[ -d "$BASE/$d" ]] && apply 750 "$BASE/$d"
done

while IFS= read -r f; do apply 755 "$f"; done < <(find "$BASE/scripts" -maxdepth 1 -name "*.sh" 2>/dev/null)
while IFS= read -r f; do apply 640 "$f"; done < <(find "$BASE/server" -type f \( -name "*.properties" -o -name "*.yml" -o -name "*.json" \) 2>/dev/null)
while IFS= read -r f; do apply 600 "$f"; done < <(find "$BASE" -type f \( -name "*.env" -o -name "*.key" -o -name "*.tar.gz" \) 2>/dev/null)

open_write=$(find "$BASE" -perm -o+w -not -path "*/.git/*" 2>/dev/null | wc -l)
if (( open_write > 0 )); then
  warn "พบ $open_write ไฟล์ที่คนอื่นเขียนได้ — ตรวจด้วย: find $BASE -perm -o+w"
  exit 1
fi

log "สิทธิ์ถูกต้องทั้งหมด"
```

**อธิบาย:** `umask 027` กันไฟล์ใหม่หลุดสิทธิ์ · `find ... -exec` ถูกแทนด้วย `while read` เพื่อให้ log ทีละไฟล์ · การตรวจ `-perm -o+w` ปิดท้ายคือ audit ที่รันซ้ำได้ (idempotent)

## G. แบบฝึกหัด

### G.1 พื้นฐาน

สร้างไฟล์ 4 ไฟล์ใน `/tmp/perm-lab` แล้วตั้งสิทธิ์ให้ได้ผลตามนี้ (ห้ามใช้ `chown`):
- `a.txt` อ่านได้ทุกคน แต่เขียนได้เฉพาะเจ้าของ
- `b.txt` เฉพาะเจ้าของอ่าน/เขียน
- `c.sh` เจ้าของรันได้ กลุ่มอ่านได้ คนอื่นไม่มีสิทธิ์
- `d/` เจ้าของเข้าได้อย่างเดียว (ห้าม list)

เขียนคำสั่งทั้งหมดลง `notes/perm-answers.md` พร้อมผล `ls -l`

### G.2 ประยุกต์

เขียน `scripts/audit-permissions.sh` ที่สแกนโฟลเดอร์เซิร์ฟเวอร์แล้วรายงาน:

1. ไฟล์ที่ `others` เขียนได้ (`-perm -o+w`)
2. ไฟล์ที่ `others` อ่านได้และมีคำว่า `password|token|secret` ในชื่อ
3. ไฟล์ `.jar` ที่ไม่ใช่ 644
4. ไฟล์ script ที่ไม่ใช่ 755
5. โฟลเดอร์ที่ไม่มี `x` สำหรับเจ้าของ (จะทำให้เข้าไม่ได้)

สรุปเป็นตาราง + exit 1 ถ้าพบข้อ 1 หรือ 2

### G.3 คำถามตรวจสอบความเข้าใจ

1. ทำไมโฟลเดอร์ `rwxrwxrwx` ถึงอันตรายกว่าไฟล์ `rwxrwxrwx` มาก
2. `umask 027` ทำให้ไฟล์ที่สร้างใหม่มีสิทธิ์เท่าไร และเพราะอะไรจึงไม่ใช่ 750
3. ถ้า `world/` เป็นของ `root` แต่เซิร์ฟเวอร์รันด้วยผู้ใช้ `minecraft` จะเกิดอะไรขึ้นตอนเซฟโลก

## H. Challenge — ระบบสิทธิ์ของทีมเล็ก

สถานการณ์: คุณมีผู้ช่วย 2 คน (`builder`, `moderator`) ต้องทำงานบนเซิร์ฟเวอร์เดียวกัน:

- `builder` ต้องแก้ไฟล์ world/และอ่าน log ได้ แต่ห้ามอ่านไฟล์สำรอง
- `moderator` ต้องอ่าน log และไฟล์ผู้เล่นได้ แต่ห้ามแก้ไฟล์ใด ๆ
- คุณ (เจ้าของ) ต้องทำได้ทุกอย่าง
- ทั้งสามคนห้ามเข้าถึงไฟล์ `secrets.env`

**สิ่งที่ต้องส่ง:**
1. แผนการใช้ **กลุ่ม** (group) แทนการให้สิทธิ์รายคน — เพราะอะไรถึงดีกว่า
2. ชุดคำสั่งสร้างผู้ใช้/กลุ่ม/โฟลเดอร์/สิทธิ์ที่รันได้จริงในเครื่องทดสอบ (`/tmp/team-lab`)
3. ตารางตรวจสอบ: ใครทำอะไรได้/ไม่ได้ พร้อมผลทดสอบจริง (ลองสลับผู้ใช้ด้วย `sudo -u`)
4. อธิบายว่าทำไมวิธีนี้ยัง **ไม่พอ** สำหรับเซิร์ฟเวอร์จริง และต้องเพิ่มอะไร (ใบ้: sudo rule, ACL, systemd hardening)

> 💡 ถ้าเครื่องไม่มีสิทธิ์ `sudo` ให้จำลองด้วยโฟลเดอร์+tests แทน และเขียนอธิบายว่าแต่ละคำสั่งจะทำอะไร

## K. Troubleshooting

| อาการ | สาเหตุ | วิธีแก้ |
| --- | --- | --- |
| `cd: Permission denied` | โฟลเดอร์ไม่มี `x` | `chmod u+x dir` |
| `ls: Permission denied` แต่ `cat ไฟล์` ได้ | มี `x` ไม่มี `r` | เพิ่ม `chmod u+r dir` ถ้าต้องการ list |
| `./script.sh: Permission denied` | ไม่มี `x` บนไฟล์ | `chmod 755 script.sh` |
| แก้ไฟล์ได้แต่เซิร์ฟเวอร์เขียนไม่ได้ | เจ้าของไฟล์เป็น root | `sudo chown -R $USER:$USER path` |
| `chmod: Operation not permitted` | ไม่ใช่เจ้าของ | ใช้ `sudo` หรือขอเจ้าของเปลี่ยน |
| ไฟล์ใหม่ที่สร้างมีสิทธิ์กว้างเกิน | umask 022 | `umask 027` ก่อนสร้าง |
| ตั้ง `chmod -R 777` แล้วยังพัง | ปัญหาอยู่ที่เจ้าของ/บริบท ไม่ใช่สิทธิ์ | ตรวจ `ls -l` แล้วแก้ `chown` แทน |
| `sudo chown -R` เปลี่ยนเจ้าของทั้งระบบ | พิมพ์พาธผิด | ใช้ `pwd` + `ls -d` ยืนยันก่อนทุกครั้ง |

## L. สรุป

- สิทธิ์ = 3 ระดับ (user/group/others) × 3 สิทธิ์ (rwx) → เขียนเป็นเลขฐานแปดได้
- `r` บนโฟลเดอร์ = ดูรายชื่อ, `x` = เข้าไปได้/ผ่านได้ — คนละหน้าที่
- มาตรฐานโปรเจกต์: 750 โฟลเดอร์, 755 script, 640 config, 600 ไฟล์ลับ/สำรอง
- `umask` กำหนดสิทธิ์ของไฟล์ใหม่ — ตั้ง 027 ในทุก script ที่สร้างข้อมูลผู้เล่น
- ห้ามรันเซิร์ฟเวอร์ด้วย root; audit ด้วย `find -perm -o+w` เป็นนิสัย
