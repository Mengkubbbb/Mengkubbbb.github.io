## A. เป้าหมาย

จบบทนี้คุณจะ:

## C. แนวคิด

### C.1 ตัวแปรใน bash: กฎที่ต้องจำ 5 ข้อ

```bash
name="Mengkub"        # ✅ ถูก
name = "Mengkub"      # ❌ bash คิดว่า "name" คือคำสั่ง
level=12              # ✅ ตัวเลขก็เก็บเป็นข้อความ (bash ไม่มีชนิดข้อมูล)
echo "$name"          # ✅ แนะนำเสมอ
echo $name            # ⚠️ ใช้ได้ แต่จะพังเมื่อค่ามีช่องว่าง
readonly MAX=60       # ✅ ล็อกค่าไว้ กันเขียนทับโดยไม่ตั้งใจ
```

1. **ห้ามมีช่องว่างรอบ `=`**
2. ค่าทุกอย่างเป็น **ข้อความ** (bash ไม่มี `int`) — ต้องแปลงเองเมื่อคำนวณ
3. ใช้ `${name}` เมื่อต่อกับข้อความอื่น: `"${name}_data"` (ถ้าเขียน `"$name_data"` bash จะหาตัวแปรชื่อ `name_data`)
4. ตัวแปรมีอายุแค่ใน **เชลล์ที่สร้างมัน** — ถ้าอยากให้ child process เห็นด้วยต้อง `export`
5. `local` ใช้ภายในฟังก์ชัน เพื่อไม่ให้ไปทับตัวแปรข้างนอก (จะได้ใน Day 11)

### C.2 อาร์กิวเมนต์: ข้อมูลที่ผู้ใช้ส่งเข้ามา

```bash
#!/usr/bin/env bash
echo "ชื่อไฟล์ script : $0"     # ./greet.sh
echo "อาร์กิวเมนต์ 1  : $1"
echo "อาร์กิวเมนต์ 2  : $2"
echo "จำนวนอาร์กิวเมนต์: $#"
echo "ทั้งหมด (แยกชิ้น): $@"    # ไม่ควรใช้แบบไม่มีเครื่องหมายคำพูด
```

| ตัวแปร | ความหมาย | ตัวอย่างผล |
| --- | --- | --- |
| `$0` | ชื่อ script | `./greet.sh` |
| `$1`, `$2`, … | อาร์กิวเมนต์ตามลำดับ | `$1` = `Somchai` |
| `$#` | จำนวนอาร์กิวเมนต์ | `2` |
| `"$@"` | อาร์กิวเมนต์ทั้งหมด แยกเป็นชิ้นอย่างถูกต้อง | `"Somchai" "12"` |
| `$*` | ทั้งหมดรวมเป็นสตริงเดียว | `Somchai 12` |
| `$?` | exit code ของคำสั่งก่อนหน้า | `0` = สำเร็จ |
| `$$` | PID ของ script | `48231` |

**ค่าเริ่มต้นเมื่อผู้ใช้ไม่ใส่:**

```bash
name="${1:-ผู้เล่นใหม่}"     # ถ้า $1 ว่างหรือไม่มี → ใช้ "ผู้เล่นใหม่"
count="${2:-1}"              # ค่าเริ่มต้น 1
```

> 💡 `"$@"` ต้องมีเครื่องหมายคำพูดเสมอ. ถ้าเขียน `$@` เฉย ๆ อาร์กิวเมนต์ที่มีช่องว่างจะถูกตัดเป็นหลายชิ้น — บั๊กคลาสสิกที่หาเป็นชั่วโมง

### C.3 รับข้อมูลจากผู้ใช้ด้วย `read`

```bash
read -rp "ใส่ชื่อตัวละคร: " char_name      # -r = ไม่ตีความ \ , -p = แสดงข้อความ
read -rp "เลเวล (1-60): " char_level
read -rp "ชื่อเซิร์ฟเวอร์ [Eclipse]: " server
server="${server:-Eclipse}"                 # ค่าเริ่มต้นถ้าผู้ใช้กด Enter
read -rt 5 -p "กด Enter ภายใน 5 วิ (ไม่กดก็ผ่าน): " _ || echo "หมดเวลา — ข้ามไป"
```

`read` จะคืน exit code ≠ 0 เมื่ออ่านไม่ได้ (เช่น ไม่มีอินพุตในโหมด script) — ต้องตรวจด้วย `if ! read ...` ถ้า script ต้องรันแบบไม่มีคนเฝ้า

### C.4 Quoting: จุดที่มือใหม่พังมากที่สุด

```bash
file="my world"          # มีช่องว่าง
rm $file                 # ❌ ลบ "my" และ "world" (สองไฟล์!)
rm "$file"               # ✅ ลบไฟล์เดียวชื่อ "my world"

echo 'Cost: $100'        # single quote = ทุกอย่างคือข้อความดิบ
echo "Cost: $100"        # double quote = ขยายตัวแปร (ที่นี่ $1 แล้วตามด้วย 00)
printf '%s\n' "$file"    # ✅ ปลอดภัยที่สุดเมื่อจะพิมพ์ค่าออกมา
```

**กฎ 3 ข้อที่ใช้ได้ตลอดชีวิต:**

1. ตัวแปรที่อาจมีช่องว่าง → ใส่ `"..."` ทุกครั้ง
2. ข้อความที่ไม่อยากให้ขยายตัวแปร → single quote
3. จะพิมพ์ข้อมูลออกจอ → `printf` ดีกว่า `echo` (เพราะ `echo -e` ทำงานต่างกันในแต่ละระบบ)

### C.5 Exit code: ภาษาที่ script ใช้คุยกับคนอื่น

| ค่า | ความหมาย |
| --- | --- |
| `0` | สำเร็จ |
| `1` | ผิดพลาดทั่วไป |
| `2` | ใช้คำสั่งผิดรูปแบบ (argument ผิด) |
| `126` | ไฟล์ไม่สามารถ execute ได้ |
| `127` | ไม่พบคำสั่ง |

```bash
set -euo pipefail
# -e : เจอคำสั่งที่ fail ให้หยุดทันที (ไม่ทำงานต่อกับข้อมูลเสีย)
# -u : ใช้ตัวแปรที่ยังไม่ประกาศ = error (จับพิมพ์ผิด)
# -o pipefail : ถ้าคำสั่งในท่อพัง ให้ถือว่าท่อพังด้วย
```

ส่งข้อความผิดพลาดไป **stderr** ไม่ใช่ stdout:

```bash
echo "ข้อผิดพลาด: ต้องระบุชื่อ" >&2
exit 2
```

**ทำไมสำคัญ?** เพราะถ้าข้อความ error ปนไปใน stdout แล้วคุณเอาผลลัพธ์ไปประมวลผลต่อ (Day 12) ข้อมูลจะเสียทั้งชุด

## D. ลงมือทำ (ทำตามลำดับ ทดสอบทุกขั้น)

### ขั้นที่ 1: สร้างไฟล์และโครงเริ่มต้น

```bash
cd ~/minecraft-mmo-dev/scripts
cat > greet.sh <<'EOF'
#!/usr/bin/env bash
set -uo pipefail

readonly SCRIPT_NAME="$(basename "$0")"
readonly VERSION="0.1.0"

usage() {
  cat <<HELP
วิธีใช้: $SCRIPT_NAME [ชื่อ] [เลเวล]

ตัวอย่าง:
  $SCRIPT_NAME Somchai 12
  $SCRIPT_NAME              # จะถามชื่อและเลเวล
HELP
}
EOF
chmod +x greet.sh
bash -n greet.sh && echo "syntax OK"
```

**สังเกต:** เราใช้ `<<'EOF'` (มี single quote) ตอนเขียนไฟล์ เพื่อให้ `$` ทั้งหมดถูกเก็บไว้เป็นข้อความ ไม่ถูกขยายตอนเขียน — ถ้าใช้ `<<EOF` ตัวแปรจะถูกแทนค่าทันทีและไฟล์จะเพี้ยน

### ขั้นที่ 2: เพิ่มการอ่านอาร์กิวเมนต์

```bash
cat >> greet.sh <<'EOF'
```

### ขั้นที่ 3: ถามเมื่อผู้ใช้ไม่ได้ให้ค่า

```bash
cat >> greet.sh <<'EOF'

  read -rp "ใส่ชื่อตัวละคร: " name
fi

  read -rp "ใส่เลเวล (1-60): " level
```

### ขั้นที่ 4: ตรวจสอบค่าและแสดงผล

```bash
cat >> greet.sh <<'EOF'

# ตรวจว่าเลเวลเป็นตัวเลข และอยู่ในช่วงที่เกมยอมรับ
if ! [[ "$level" =~ ^[0-9]+$ ]]; then
  echo "ข้อผิดพลาด: เลเวลต้องเป็นตัวเลข (ได้รับ: $level)" >&2
  exit 2
fi
if (( level < 1 || level > 60 )); then
  echo "ข้อผิดพลาด: เลเวลต้องอยู่ระหว่าง 1-60 (ได้รับ: $level)" >&2
  exit 2
fi

printf 'สวัสดี %s — เลเวล %s\n' "$name" "$level"
printf 'ยินดีต้อนรับสู่ Eclipse MMO RPG\n'
exit 0
EOF
chmod +x greet.sh
bash -n greet.sh && echo "syntax OK"
```

### ขั้นที่ 5: ทดสอบทั้ง 6 กรณี

```bash
./greet.sh Somchai 12        ; echo "exit=$?"
./greet.sh --help            ; echo "exit=$?"
./greet.sh "Som Chai" 60     ; echo "exit=$?"
./greet.sh Somchai abc       ; echo "exit=$?"
./greet.sh Somchai 99        ; echo "exit=$?"
printf 'Nong\n5\n' | ./greet.sh ; echo "exit=$?"
```

**ผลที่ต้องได้ (จดไว้ใน notes ของคุณ):**

| คำสั่ง | ผลที่คาด | exit |
| --- | --- | --- |
| `./greet.sh Somchai 12` | `สวัสดี Somchai — เลเวล 12` | 0 |
| `./greet.sh --help` | แสดงวิธีใช้ | 0 |
| `./greet.sh "Som Chai" 60` | `สวัสดี Som Chai — เลเวล 60` (ชื่อไม่แตก) | 0 |
| `./greet.sh Somchai abc` | error เรื่องตัวเลข (ไป stderr) | 2 |
| `./greet.sh Somchai 99` | error เรื่องช่วง 1-60 | 2 |
| `printf ... \| ./greet.sh` | ใช้ค่าที่ pipe เข้ามา | 0 |

> ⚠️ ถ้าข้อ 5 ค้างรอ input แปลว่า `read` ยังทำงานอยู่ — เพราะในท่อ `read` อ่านจาก stdin ที่ pipe มาให้แล้ว จึงต้องมีข้อมูลพอสำหรับทั้งสองคำถาม

## F. โค้ดตัวอย่าง (ฉบับสมบูรณ์ — ใช้เทียบกับของคุณ)

```bash
#!/usr/bin/env bash
# greet.sh — ทักทายผู้เล่นพร้อมตรวจสอบข้อมูล (Day 08)
set -uo pipefail

readonly SCRIPT_NAME="$(basename "$0")"
readonly MIN_LEVEL=1
readonly MAX_LEVEL=60

usage() {
  cat <<HELP
วิธีใช้: $SCRIPT_NAME [ชื่อ] [เลเวล]

ตัวอย่าง:
  $SCRIPT_NAME Somchai 12
  $SCRIPT_NAME              # จะถามชื่อและเลเวล

ตัวเลือก:
  -h, --help    แสดงข้อความนี้
HELP
}

case "${1:-}" in
  -h|--help|help) usage; exit 0 ;;
esac

name="${1:-}"
level="${2:-}"

if [ -z "$name" ]; then
  read -rp "ใส่ชื่อตัวละคร: " name || true
fi
name="${name:-ผู้เล่นใหม่}"

if [ -z "$level" ]; then
  read -rp "ใส่เลเวล (${MIN_LEVEL}-${MAX_LEVEL}): " level || true
fi
level="${level:-1}"

if ! [[ "$level" =~ ^[0-9]+$ ]]; then
  echo "ข้อผิดพลาด: เลเวลต้องเป็นตัวเลข (ได้รับ: $level)" >&2
  exit 2
fi

if (( level < MIN_LEVEL || level > MAX_LEVEL )); then
  echo "ข้อผิดพลาด: เลเวลต้องอยู่ระหว่าง ${MIN_LEVEL}-${MAX_LEVEL} (ได้รับ: $level)" >&2
  exit 2
fi

printf 'สวัสดี %s — เลเวล %s\n' "$name" "$level"
printf 'ยินดีต้อนรับสู่ Eclipse MMO RPG\n'
exit 0
```

**อธิบายจุดสำคัญ 4 จุด:**

1. `readonly` ที่ค่าคงที่ → ถ้าเผลอเขียนทับ bash จะฟ้องทันที (ดีกว่าปล่อยให้ค่าเพี้ยนเงียบ ๆ)
2. `case "${1:-}"` — ใช้ `:-` เพื่อไม่ให้ `set -u` ทำให้ script ตายตอนไม่ใส่อาร์กิวเมนต์เลย
3. `[[ "$level" =~ ^[0-9]+$ ]]` ตรวจว่าเป็นตัวเลข **ก่อน** ใช้ `(( ))` — ถ้าไม่ตรวจก่อน `(( abc < 1 ))` จะตีความเป็นชื่อตัวแปรแล้วกลายเป็น 0 (บั๊กเงียบ!)
4. `>&2` + `exit 2` แยก "ข้อความผิดพลาด" ออกจาก "ผลลัพธ์" และบอกคนอื่นว่าเป็นปัญหาการใช้คำสั่ง

### G.2 ประยุกต์

เขียน `scripts/player-info.sh` ที่:

1. รับชื่อผู้เล่นเป็นอาร์กิวเมนต์ (ถ้าไม่มี → ถาม)
2. รับค่าสถานะจากผู้ใช้ 3 ค่า: HP, MP, Level (ถามทีละค่า)
3. ตรวจทุกค่า: HP 1–1000, MP 0–500, Level 1–60
4. แสดงตารางสรุป 3 บรรทัดให้ตรงคอลัมน์ (ใช้ `printf '%-10s %5s\n'`)
5. ถ้าค่าใดผิด → บอกว่าค่าที่ผิดคือช่องไหน และ exit 2 (ไม่ต้องถามซ้ำ)

## H. Challenge — `roll.sh` ตัวจำลองการทอยเต๋า

สร้าง `scripts/roll.sh` ที่:

- รับ `--dice N` (จำนวนลูก 1–10) และ `--sides M` (จำนวนหน้า 2–100) ค่าเริ่มต้น 1d6
- แสดงผลแต่ละลูกและผลรวม
- รับ `--repeat K` เพื่อทอยซ้ำ K ครั้ง แล้วสรุปค่าเฉลี่ย (ทศนิยม 2 ตำแหน่ง)
- ถ้า argument ผิด → ข้อความช่วยเหลือ + exit 2
- ต้องรันได้ทั้งแบบ `./roll.sh` (ใช้ค่าเริ่มต้น) และ `./roll.sh --dice 3 --sides 20 --repeat 100`

**เกณฑ์ผ่าน:** ทอย 100 ครั้งด้วย `--sides 6` ค่าเฉลี่ยต้องอยู่ระหว่าง 3.0–4.0 (ถ้าได้ 1 หรือ 6 ตลอด = bug การสุ่ม)

> 💡 ใช้ `$RANDOM` (0–32767) แล้วแปลง: `$(( RANDOM % sides + 1 ))`. ระวัง: `%` ทำให้ผลเอียงเล็กน้อย (modulo bias) — เขียนอธิบายใน `notes/roll-bias.md` ว่าทำไม และจะแก้อย่างไรใน Month 2

## K. Troubleshooting

| อาการ | สาเหตุ | วิธีแก้ |
| --- | --- | --- |
| `name: command not found` | มีช่องว่างรอบ `=` | `name="..."` ไม่มีช่องว่าง |
| `unbound variable` แล้ว script ตาย | `set -u` + ใช้ตัวแปรที่ยังไม่ประกาศ | ใช้ `${var:-}` หรือประกาศก่อน |
| `[: ==: unary operator expected` | ตัวแปรว่างและไม่ได้ใส่ quote | `[ "$x" = "y" ]` (quote เสมอ) |
| script ค้างรอ input | มี `read` ที่ไม่ได้ตั้งใจ | ตรวจว่ามีการ pipe ข้อมูลมาให้ครบทุก `read` |
| `Permission denied` | ยังไม่ `chmod +x` | `chmod +x greet.sh` |
| ชื่อที่มีช่องว่างแตกเป็นหลายคำ | ไม่ได้ quote `$var` | `"$var"` ทุกครั้ง |
| `(( abc < 1 ))` ไม่ error แต่ผลผิด | `(( ))` ตีความ non-numeric เป็นชื่อตัวแปร | ตรวจด้วย regex ก่อนคำนวณ |
| ข้อความไทยเพี้ยน | locale ไม่ใช่ UTF-8 | `export LANG=th_TH.UTF-8` หรือ `C.UTF-8` |

## L. สรุป

- ตัวแปร bash = ข้อความ, ห้ามมีช่องว่างรอบ `=`, ต้อง quote เมื่อค่าอาจมีช่องว่าง
- อาร์กิวเมนต์: `$1`…`$N`, `$#`, `"$@"`; ใช้ `${1:-ค่าเริ่มต้น}` เพื่อกันค่าว่าง
- `read -rp` รับข้อมูลจากผู้ใช้; ในโหมดอัตโนมัติต้อง pipe ข้อมูลให้ครบ
- exit code คือสัญญา: `0` สำเร็จ, `2` ใช้คำสั่งผิด, ข้อความ error ไป stderr
- `set -uo pipefail` ทำให้ bug โผล่เร็ว (Day 27 จะเพิ่ม `-e` พร้อมจัดการ edge case ครบ)

**บทต่อไป (Day 09):** เงื่อนไข `if` / `case` และการตรวจสอบค่าเชิงลึก — เราจะเขียน `check-price.sh` ที่ตรวจราคาไอเทมในร้านค้าเกม และใช้ `case` จัดการระดับความหายาก
