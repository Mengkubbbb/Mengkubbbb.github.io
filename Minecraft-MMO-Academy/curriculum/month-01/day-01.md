## C. แนวคิด

### C.1 Terminal กับ Shell ต่างกันอย่างไร

ลองคิดถึง Minecraft:
- **Shell** = เหมือน "ตัว interprete คำสั่ง" ในเกม ที่คอยรับคำสั่งจากผู้เล่นแล้วไปทำ (เช่นผู้เล่นพิมพ์ `/give` แล้วระบบไปให้ของ)
- **Terminal** = เหมือน "หน้าจอแชท" ที่เราใช้พิมพ์คำสั่งนั้น

พูดง่าย ๆ: Terminal คือหน้าต่าง **Shell** คือตัวทำงาน คำสั่งที่พิมพ์จะถูก Shell อ่านแล้วส่งให้ระบบปฏิบัติการ

Shell ที่ใช้ในหลักสูตรนี้คือ **bash** (ตรวจได้ด้วย `echo $SHELL`)

### C.2 ทำไมเซิร์ฟเวอร์ต้องใช้ Terminal

เซิร์ฟเวอร์ Minecraft เป็นโปรแกรมที่:
1. ต้องรันต่อเนื่องเป็นชั่วโมง/วัน (ไม่มีหน้าต่าง GUI ให้กด)
2. ดูข้อมูลการทำงานจาก **log** (ไฟล์บันทึก)
3. ต้องสำรองข้อมูลอัตโนมัติตอนตี 4 ทุกวัน (ทำผ่าน UI ไม่ได้)
4. ต้องรันบนเครื่องที่ไม่มีการ์ดจอ (VPS) ได้

→ งานพวกนี้ทำผ่าน Terminal ทั้งหมด และนี่คือเหตุผลที่เราต้องคล่อง Terminal ก่อนเขียนปลั๊กอิน

### C.3 พาธ (Path) = ที่อยู่ของไฟล์

ในเกม Minecraft เรามีพิกัดบอกว่าเราอยู่ไหน ใน Linux เราก็มี "พิกัด" ของไฟล์ เรียกว่า **path**

| ชนิด | หน้าตา | ความหมาย |
| --- | --- | --- |
| Absolute path | `/home/mengkub/minecraft-mmo-dev/server` | บอกครบตั้งแต่รากของระบบ (ขึ้นต้นด้วย `/` เสมอ) |
| Relative path | `server/plugins` | เทียบจากโฟลเดอร์ที่เรายืนอยู่ตอนนี้ |

**สัญลักษณ์ที่ต้องรู้:**

| สัญลักษณ์ | ความหมาย | ตัวอย่าง |
| --- | --- | --- |
| `/` | โฟลเดอร์ราก (root) ของระบบทั้งหมด | `/etc` |
| `~` | โฟลเดอร์บ้านของผู้ใช้ปัจจุบัน | `~` = `/home/<ชื่อคุณ>` |
| `.` | โฟลเดอร์นี้ (ปัจจุบัน) | `./start.sh` |
| `..` | โฟลเดอร์แม่ (ขึ้นไปหนึ่งชั้น) | `cd ..` |

> ⚠️ **ข้อผิดพลาดที่มือใหม่เจอบ่อยที่สุด**: เข้าใจผิดว่า `~` กับ `/` เหมือนกัน
> `~` คือบ้านของคุณ `/` คือรากของทั้งเครื่อง (ที่อยู่ของไฟล์ระบบ — ห้ามแตะ)

### C.4 ทำไมต้องมี "โฟลเดอร์ทำงาน" แยก

ถ้าเราทำทุกอย่างในโฟลเดอร์บ้านตรง ๆ (หรือแย่กว่านั้นคือ `/tmp` ที่ลบเองทุกครั้งรีบูต) เราจะ:
- หาไฟล์ไม่เจอในอีก 3 วัน
- เผลอรันคำสั่งลบโดยไม่ตั้งใจในโฟลเดอร์ที่สำคัญ

หลักสูตรนี้จึงใช้โฟลเดอร์เดียวชื่อ `~/minecraft-mmo-dev/` เป็นบ้านของงานทั้งหมด

## D. ตัวอย่าง

### D.1 ทดลองคำสั่งแรก (รันได้เลย)

```bash
whoami          # ฉันเป็นใครในระบบนี้
pwd             # ตอนนี้ยืนอยู่ที่โฟลเดอร์ไหน
ls              # มีไฟล์อะไรในโฟลเดอร์นี้
```

**อธิบายทีละคำสั่ง**

| คำสั่ง | ย่อจาก | ทำอะไร |
| --- | --- | --- |
| `whoami` | who am I | บอกชื่อผู้ใช้ปัจจุบัน (สำคัญเวลารัน script บนหลายเครื่อง) |
| `pwd` | print working directory | บอกพาธแบบเต็มของโฟลเดอร์ปัจจุบัน |
| `ls` | list | แสดงรายการไฟล์/โฟลเดอร์ (ไม่แสดงไฟล์ที่ขึ้นต้นด้วย `.` เช่น `.bashrc`) |

### D.2 โครงสร้างเซิร์ฟเวอร์ Minecraft ที่เซิร์ฟเวอร์จริงใช้

เมื่อรัน Paper ครั้งแรก โปรแกรมจะสร้างไฟล์/โฟลเดอร์เหล่านี้ (ยังไม่ต้องจำทั้งหมด — รู้จักพอ):

```text
server/
├── paper-26.3-226.jar     ← ตัวเซิร์ฟเวอร์
├── eula.txt               ← ข้อตกลงการใช้งาน (ต้องยอมรับก่อนเปิด)
├── server.properties      ← ไฟล์ตั้งค่าหลัก
├── start.sh               ← script ที่เราจะเขียนเองไว้เปิดเซิร์ฟเวอร์
├── plugins/               ← ปลั๊กอินทั้งหมดของเรา
├── logs/                  ← log รายวัน (ของจริงจะเยอะมาก)
├── world/                 ← โลกหลัก
├── world_nether/          ← โลกนรก
├── world_the_end/         ← โลกอวสาน
└── config/                ← ไฟล์ตั้งค่าของปลั๊กอินบางตัว
```

เราจะทำให้เหมือนกัน แต่ **แยกเป็น 2 ชั้น** เพื่อความปลอดภัย:

```text
~/minecraft-mmo-dev/
├── server/        ← ตัวเซิร์ฟเวอร์ทดสอบ (จะลบ/เริ่มใหม่ได้ตลอด)
├── scripts/       ← script ที่เราเขียนเอง
├── notes/         ← จดบันทึกการเรียนรู้
├── backups/       ← ไฟล์สำรองข้อมูล
├── lab/           ← โฟลเดอร์ทดลอง (ที่นี่ลบได้ ไม่มีผลกับอะไร)
└── academy/       ← โฟลเดอร์เก็บหลักสูตรนี้ (คัดลอกไว้ดูแบบไม่ต้องต่อเน็ต)
```

เหตุผลที่ต้องมีโฟลเดอร์ `lab/`: เพื่อให้เราทดลองคำสั่งที่ "อันตราย" (เช่น `rm`) ได้อย่างสบายใจ

## E. ลงมือทำ (ทำตามลำดับ ห้ามข้าม)

### ขั้นที่ 1: เปิด Terminal และตรวจสภาพแวดล้อม

```bash
cat /etc/os-release | head -3
echo $SHELL
```

**ผลลัพธ์ที่คาดหวัง:** เห็นชื่อระบบปฏิบัติการ (เช่น CachyOS/Arch) และ `/bin/bash` หรือ `/usr/bin/bash`

### ขั้นที่ 2: ไปที่โฟลเดอร์บ้าน

```bash
cd ~
pwd
```

**ผลลัพธ์ที่คาดหวัง:** `pwd` แสดงพาธที่ลงท้ายด้วยชื่อผู้ใช้ของคุณ เช่น `/home/mengkub`

### ขั้นที่ 3: สร้างโฟลเดอร์ทำงานทั้งหมด

```bash
mkdir -p ~/minecraft-mmo-dev/{server,scripts,notes,backups,lab,academy}
```

**อธิบาย:**
- `mkdir` = make directory (สร้างโฟลเดอร์)
- `-p` = สร้างโฟลเดอร์แม่ให้ด้วยถ้ายังไม่มี และไม่ error ถ้ามีอยู่แล้ว
- `{server,scripts,...}` = **brace expansion** คือเขียนสั้น ๆ แล้ว shell จะขยายเป็นหลายพาธให้เอง

ถ้าไม่เข้าใจ brace expansion ให้ลองเทียบผลลัพธ์สองคำสั่งนี้ (แบบไม่สร้างจริง ใช้ `echo`):

```bash
echo mkdir -p ~/test/{a,b,c}
echo mkdir -p ~/test/a ~/test/b ~/test/c
```

ทั้งสองบรรทัดพิมพ์ผลเหมือนกัน — นี่คือสิ่งที่ shell ทำให้เราก่อนส่งคำสั่งจริง

### ขั้นที่ 4: ตรวจผลลัพธ์แบบเห็นภาพ

```bash
ls -la ~/minecraft-mmo-dev
```

**ผลลัพธ์ที่คาดหวัง:** เห็น 6 โฟลเดอร์ที่สร้าง (`server  scripts  notes  backups  lab  academy`)

### ขั้นที่ 5: ทดลองการเดินทางด้วยพาธสัมพัทธ์

```bash
cd ~/minecraft-mmo-dev
pwd                 # อยู่ที่ .../minecraft-mmo-dev
cd server
pwd                 # .../minecraft-mmo-dev/server
cd ..               # ถอยขึ้นหนึ่งชั้น
pwd                 # กลับมาที่ .../minecraft-mmo-dev
cd ~                # กลับบ้าน
```

> 🛠️ **แบบฝึกหัดระหว่างทาง:** ลองตอบก่อนรัน — จาก `/home/<ชื่อคุณ>/minecraft-mmo-dev/server` ถ้าพิมพ์ `cd ../scripts` จะไปอยู่ที่ไหน? (คำตอบอยู่ท้ายบทในส่วน L)

### ขั้นที่ 6: สร้างไฟล์บันทึกโครงสร้าง

```bash
cd ~/minecraft-mmo-dev
echo "# บันทึกโครงสร้างเซิร์ฟเวอร์" > notes/structure.md
echo "" >> notes/structure.md
echo "สร้างเมื่อ: $(date '+%Y-%m-%d %H:%M')" >> notes/structure.md
cat notes/structure.md
```

**อธิบาย:** `>` เขียนทับไฟล์, `>>` ต่อท้ายไฟล์, `$(...)` เอา "ผลลัพธ์ของคำสั่ง" มาใส่ในข้อความ และ `date` คือคำสั่งบอกวันเวลา

### ขั้นที่ 7: บันทึกหลักฐาน (ใช้ใน PROGRESS.md)

```bash
ls -la ~/minecraft-mmo-dev > notes/tree-day01.txt
cat notes/tree-day01.txt
```

ถ้ามีคำสั่ง `tree` (สวยกว่า) ให้ติดตั้งในตัวจัดการแพ็กเกจของ CachyOS แล้วรัน `tree -L 1 ~/minecraft-mmo-dev`
— ถ้ายังไม่มีก็ใช้ `ls -la` แทนได้ ไม่ต้องรีบติดตั้ง

## F. โค้ดตัวอย่าง

วันนี้ยังไม่เขียนโค้ดจริง แต่มี **ชุดคำสั่ง** ที่ใช้ซ้ำได้บ่อย ๆ ให้คัดลอกเก็บไว้ใน `notes/cheatsheet.md`:

```bash
# ===== ชีตคำสั่งวันที่ 1 =====
whoami                      # ฉันคือใคร
pwd                         # อยู่ที่ไหน (พาธเต็ม)
ls -la                      # ดูไฟล์ทั้งหมดรวมไฟล์ซ่อน + สิทธิ์
cd <โฟลเดอร์>                # เข้าโฟลเดอร์
cd ..                       # ถอยขึ้นหนึ่งชั้น
cd ~                        # กลับบ้าน
mkdir -p a/b/c              # สร้างโฟลเดอร์ซ้อนกัน
echo "ข้อความ"               # พิมพ์ข้อความ
echo "ข้อความ" > f.txt      # เขียนทับไฟล์
echo "ข้อความ" >> f.txt     # ต่อท้ายไฟล์
cat f.txt                   # อ่านไฟล์ทั้งไฟล์
date                        # วันเวลาปัจจุบัน
```

**พาธไฟล์:** `~/minecraft-mmo-dev/notes/cheatsheet.md` (สร้างใหม่)

## H. Challenge (ใช้ความคิดเอง)

ออกแบบโครงสร้างโฟลเดอร์ที่รองรับ **3 สภาพแวดล้อม** ในเครื่องเดียว:
`development` (เครื่องตัวเอง), `staging` (ทดสอบกับเพื่อน), `production` (เปิดจริง)
โดยที่:
- ไฟล์ตั้งค่าของแต่ละสภาพแวดล้อมต้องไม่ทับกัน
- ยังใช้ script ชุดเดียวกันได้ (คำใบ้: ให้ script รับ argument บอกว่าจะใช้โฟลเดอร์ไหน)
- backups ต้องแยกกัน

เขียนโครงออกมาเป็นแผนผัง + อธิบาย 3 บรรทัดว่าทำไมออกแบบแบบนั้น (ยังไม่ต้องเขียน script — เดี๋ยวได้เขียนใน Day 26)

## K. Troubleshooting

| อาการ | สาเหตุที่เป็นไปได้ | วิธีตรวจสอบ | วิธีแก้ |
| --- | --- | --- | --- |
| `mkdir: cannot create directory ... Permission denied` | พยายามสร้างในโฟลเดอร์ของระบบ | พิมพ์ `pwd` ดูว่าอยู่ไหน | ออกไปที่บ้านด้วย `cd ~` แล้วสร้างใหม่ |
| `cd: no such file or directory` | พิมพ์ชื่อผิด หรือใช้พาธเทียบจากที่ผิด | `ls` ดูของจริงในโฟลเดอร์ปัจจุบัน | พิมพ์ชื่อใหม่ หรือใช้ `cd ~/minecraft-mmo-dev` |
| สร้างแล้วหาไม่เจอ | สร้างไปที่อื่น (อาจอยู่ `/` หรือ `/tmp`) | `pwd` ก่อนสร้างทุกครั้ง | ลบโฟลเดอร์ที่ผิด (เฉพาะของตัวเอง) แล้วสร้างใหม่ที่ถูก |
| ข้อความไทยเพี้ยนเป็น `????` | locale ไม่รองรับ UTF-8 | `locale` | ตั้ง `export LANG=C.UTF-8` ใน `~/.bashrc` แล้ว `source ~/.bashrc` |
| `rm` แล้วกู้ไม่ได้ | ลบแบบถาวร (ไม่มีถังขยะ) | — | ตั้งแต่นี้ให้ `ls` ตรวจพาธก่อน `rm` ทุกครั้ง |

**ถ้าติดเกิน 15 นาที:** พิมพ์ `DEBUG` แล้วส่ง 3 อย่างนี้ให้ครู → คำสั่งที่รัน, ข้อความ error ทั้งก้อน, สิ่งที่คาดว่าจะเกิด

## L. สรุป

วันนี้เราได้:
- เข้าใจว่า Terminal/Shell คืออะไร และทำไมงานเซิร์ฟเวอร์ต้องใช้มัน
- แยกพาธ absolute/relative ได้ และรู้จัก `~`, `.`, `..`, `/`
- สร้างบ้านของโปรเจกต์ `~/minecraft-mmo-dev/` ที่จะใช้ไปตลอด 365 วัน
- รู้จักโครงสร้างโฟลเดอร์จริงของเซิร์ฟเวอร์ Paper (จะได้เจอของจริงใน Day 181)

**คำตอบแบบฝึกหัดระหว่างทาง (ขั้นที่ 5):** จาก `.../minecraft-mmo-dev/server` พิมพ์ `cd ../scripts`
จะได้ `.../minecraft-mmo-dev/scripts` เพราะ `..` ถอยไปที่ `minecraft-mmo-dev` แล้วเข้า `scripts`

**บทต่อไป (Day 02):** เราจะเขียน **script ไฟล์แรก** ที่รันได้จริง — และได้เรียนเรื่องสิทธิ์ไฟล์ (`chmod`)
ซึ่งเป็นสาเหตุอันดับหนึ่งที่มือใหม่รัน script ไม่ได้
