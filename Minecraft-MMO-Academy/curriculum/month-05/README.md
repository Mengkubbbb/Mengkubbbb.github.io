# เดือนที่ 05 — Git, Gradle/Maven, Debugging และปลั๊กอินแรก

**ช่วงวัน:** Day 121–150 · **บทเรียนละเอียด:** ⏳

## เป้าหมายของเดือน
ใช้ Git ได้แบบทำงานจริง (branch/merge/แก้ conflict) เข้าใจระบบ build
และสร้างปลั๊กอิน Paper ตัวแรกที่คอมไพล์เป็น `.jar` แล้วติดตั้งบนเซิร์ฟเวอร์ได้

## สิ่งที่ต้องมีก่อนเริ่ม
- ผ่านเกณฑ์ Month 4
- เข้าใจ OOP พื้นฐาน + เขียนเทสต์ได้

## หัวข้อหลักในเดือนนี้
1. Git branch, merge, conflict, revert/reset/reflog
2. `.gitignore` สำหรับโปรเจกต์ Java และการไม่คอมมิตไฟล์ build
3. ขั้นตอนทำงานแบบ branch → PR → merge
4. Gradle: task, dependency, plugin, wrapper
5. Maven เบื้องต้นและข้อดีข้อเสีย (Paper แนะนำ Gradle)
6. อ่าน error ของ Gradle และ debug ด้วย breakpoint
7. Paper plugin: วงจรชีวิต, `plugin.yml`, `api-version`
8. สร้างโปรเจกต์ปลั๊กอินแรก + คอมไพล์ `.jar`
9. ติดตั้งปลั๊กอินบนเซิร์ฟเวอร์ทดสอบ + อ่าน log
10. โครงสร้างแพ็กเกจที่ขยายได้, คำสั่งแรก, permission แรก

## โปรเจกต์ประจำเดือน
`projects/04-first-plugin/` — ปลั๊กอิน `EclipseCore` v1 พร้อมคำสั่งของตัวเอง 1 คำสั่ง

## เกณฑ์ผ่านก่อนขึ้น Month 6
- [ ] `./gradlew build` ผ่าน และได้ไฟล์ `.jar` ใน `build/libs/`
- [ ] วาง `.jar` ใน `plugins/` ของเซิร์ฟเวอร์ทดสอบแล้ว log ขึ้นว่าโหลดสำเร็จ
- [ ] อธิบายได้ว่า `onEnable()` ถูกเรียกเมื่อไร และทำไมไม่ควรทำงานหนักในนั้น
- [ ] ใช้ `git log --oneline --graph` อ่านประวัติงานตัวเองได้

## คำเตือนของเดือนนี้
> ⚠️ ปลั๊กอินจากอินเทอร์เน็ตส่วนใหญ่เขียนด้วย API รุ่นเก่า (1.21.x) — ให้ยึดเอกสาร https://docs.papermc.io/paper/dev/ เป็นหลักเสมอ
> ⚠️ `/reload` ไม่ใช่คำสั่งทดสอบปลั๊กอิน; ให้รีสตาร์ทเซิร์ฟเวอร์เมื่อทดสอบโค้ดที่โหลดตอนเริ่มระบบ
