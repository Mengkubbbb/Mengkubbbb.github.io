# GLOSSARY.md — คำศัพท์ของหลักสูตร (ภาษาไทย + ตัวอย่างจาก Minecraft)

> 📖 วิธีใช้: เมื่อเจอคำใหม่ในบทเรียน ให้เพิ่มคำนั้นที่นี่ **ด้วยคำอธิบายของตัวเอง** (การเขียนด้วยตัวเองคือการทบทวนที่ดีที่สุด)
> รูปแบบ: คำศัพท์ | ความหมายแบบเข้าใจง่าย | ตัวอย่างในโปรเจกต์เรา

---

## 1. Terminal / Linux

| คำ | ความหมายง่าย ๆ | ตัวอย่างในโปรเจกต์ |
| --- | --- | --- |
| **Terminal (เทอร์มินัล)** | หน้าต่างที่เราพิมพ์คำสั่งให้คอมทำงาน | ที่เรารัน `./gradlew build` และ `./start.sh` |
| **Shell (เชลล์)** | โปรแกรมที่อ่านคำสั่งที่เราพิมพ์แล้วไปสั่งระบบอีกที (ตัวที่พบบ่อย: `bash`) | ตอนเปิด Terminal จะมีตัวนี้รอรับคำสั่ง |
| **Command (คำสั่ง)** | ชื่อโปรแกรมที่พิมพ์เพื่อให้ทำงาน | `ls`, `cd`, `java`, `git` |
| **Argument** | ค่าที่ต่อท้ายคำสั่งเพื่อบอกว่าให้ทำกับอะไร | ใน `cp world world-backup` → `world-backup` คือ argument |
| **Working directory** | โฟลเดอร์ปัจจุบันที่เรายืนอยู่ | `pwd` บอกว่าเราอยู่ที่ `~/minecraft-mmo-dev` |
| **Absolute path** | ที่อยู่เต็ม เริ่มจาก `/` | `/home/mengkub/minecraft-mmo-dev/server` |
| **Relative path** | ที่อยู่เทียบจากโฟลเดอร์ปัจจุบัน | `./scripts/backup.sh` |
| **`~` (tilde)** | ย่อของโฟลเดอร์บ้านของผู้ใช้ | `~/minecraft-mmo-dev` |
| **`PATH`** | รายการโฟลเดอร์ที่เชลล์จะไปหาคำสั่ง | ถ้า `java` ไม่อยู่ใน `PATH` จะได้ `command not found` |
| **Environment variable** | ตัวแปรของระบบที่ทุกโปรแกรมอ่านได้ | `JAVA_HOME`, `PATH` |
| **Pipe `|`** | ส่งผลลัพธ์ของคำสั่งแรกไปเป็นข้อมูลเข้าของคำสั่งที่สอง | `cat logs/latest.log \| grep ERROR` |
| **Redirect `>` / `>>`** | เก็บผลลัพธ์ลงไฟล์ (เขียนทับ / ต่อท้าย) | `./start.sh >> server-console.log 2>&1` |
| **`2>&1`** | ส่งข้อความ error ไปรวมกับข้อความปกติ | ใช้ตอนรันเซิร์ฟเวอร์ใน background |
| **Wildcard `*`** | แทนชื่ออะไรก็ได้ | `rm logs/*.log.gz` |
| **Permission (สิทธิ์)** | ใครอ่าน/เขียน/รันไฟล์ได้ | `chmod +x backup.sh` ทำให้รันได้ |
| **`chmod 755`** | เจ้าของทำได้ทุกอย่าง คนอื่นอ่าน/รันได้ | script ที่แจกให้คนอื่นใช้ |
| **`sudo`** | ขอสิทธิ์ผู้ดูแลระบบ | **หลักสูตรนี้ไม่ใช้** — ไม่มีคำสั่งที่ต้อง sudo |
| **Process (โปรเซส)** | โปรแกรมที่กำลังทำงานอยู่ | เซิร์ฟเวอร์ Paper คือโปรเซส Java หนึ่งตัว |
| **Daemon / service** | โปรแกรมที่ทำงานเบื้องหลังตลอดเวลา | `sshd` ที่ให้เรา SSH เข้าเครื่อง |
| **Log (ล็อก)** | บันทึกเหตุการณ์ที่โปรแกรมเขียนไว้ให้ย้อนดู | `logs/latest.log` ของเซิร์ฟเวอร์ |
| **Port (พอร์ต)** | หมายเลขช่องทางสื่อสารของโปรแกรมหนึ่ง ๆ | เซิร์ฟเวอร์ Minecraft ใช้ UDP/TCP 25565 |
| **IP address** | ที่อยู่ของเครื่องในเครือข่าย | `127.0.0.1` = เครื่องตัวเอง (localhost) |
| **SSH** | วิธีเข้าเครื่องอื่นผ่านเครือข่ายอย่างปลอดภัย | เข้าเซิร์ฟเวอร์จริงจากเครื่องตัวเอง |
| **`rsync`** | คัดลอกไฟล์แบบฉลาด (คัดลอกเฉพาะที่เปลี่ยน) | สำรองโฟลเดอร์ `world/` |
| **`cron`** | ตัวตั้งเวลารันคำสั่งอัตโนมัติ | สำรองข้อมูลทุกวันตี 4 |
| **`systemd`** | ระบบจัดการ service ของ Linux | ให้เซิร์ฟเวอร์เปิดเองหลังรีบูต |

## 2. การเขียนโปรแกรมและ Java

| คำ | ความหมายง่าย ๆ | ตัวอย่างในโปรเจกต์ |
| --- | --- | --- |
| **Algorithm (อัลกอริทึม)** | ขั้นตอนวิธีแก้ปัญหาทีละขั้น | สูตรคำนวณดาเมจ 5 ขั้น |
| **Variable (ตัวแปร)** | กล่องเก็บค่าที่ตั้งชื่อได้ | `int hp = 100;` |
| **Type (ชนิดข้อมูล)** | ตัวแปรเก็บค่าแบบไหน | `int` (จำนวนเต็ม), `double` (ทศนิยม), `String` (ข้อความ), `boolean` (จริง/เท็จ) |
| **Primitive vs Reference** | ค่าจริง vs ที่อยู่ของออบเจกต์ | `int` เป็น primitive, `String`/`ItemStack` เป็น reference |
| **Null / NullPointerException** | ค่าที่ "ไม่มีอะไรเลย" และ error ตอนเรียกใช้ค่านั้น | เรียกความยาวของชื่อผู้เล่นที่โหลดไม่สำเร็จ |
| **Condition (เงื่อนไข)** | ถ้า...ก็ทำ... | `if (damage < 0) damage = 0;` |
| **Loop (ลูป)** | ทำซ้ำ | วนผู้เล่นทั้งหมดเพื่อหาเลือดต่ำสุด |
| **Function / Method (ฟังก์ชัน/เมธอด)** | ชุดคำสั่งที่ตั้งชื่อไว้เรียกซ้ำได้ | `calculateDamage(attacker, target)` |
| **Parameter / Argument** | ค่าที่ส่งเข้าเมธอด | `attacker` ในเมธอดด้านบน |
| **Return value** | ค่าที่เมธอดส่งกลับ | เมธอดคืนค่าดาเมจเป็น `double` |
| **Class (คลาส)** | พิมพ์เขียวของสิ่งที่เราจะสร้าง | คลาส `Item` = พิมพ์เขียวของไอเทมทุกชิ้น |
| **Object / Instance (ออบเจกต์)** | ของจริงที่สร้างจากคลาส | `new Item("ดาบเหล็ก")` |
| **Field (ฟิลด์)** | ข้อมูลที่ออบเจกต์ถือไว้ | `name`, `damage`, `rarity` |
| **Constructor** | เมธอดพิเศษที่ถูกเรียกตอนสร้างออบเจกต์ | กำหนดค่าตั้งต้นของไอเทม |
| **Encapsulation** | การซ่อนข้อมูลภายในไม่ให้ใครแก้พลาด | ตั้งฟิลด์เป็น `private`, ให้แก้ผ่านเมธอด |
| **Inheritance (สืบทอด)** | คลาสหนึ่งรับคุณสมบัติจากอีกคลาส | `Boss extends Monster` |
| **Composition** | ประกอบชิ้นส่วนแทนการสืบทอด | `Player` มี (`has-a`) `Inventory` |
| **Interface** | สัญญาว่าคลาสนี้ทำอะไรได้บ้าง | `interface Skill { void cast(...); }` |
| **Abstract class** | คลาสครึ่งสำเร็จที่บังคับให้ลูกทำส่วนที่เหลือ | คลาส `DamageFormula` |
| **Polymorphism** | เรียกวิธีเดียวกันได้หลายรูปแบบ | เรียก `cast()` กับสกิลทุกแบบ |
| **Generic** | คลาสที่ทำงานกับหลายชนิดข้อมูล | `Registry<Item>`, `Registry<Skill>` |
| **Collection** | ชุดข้อมูลแบบมีโครงสร้าง | `List`, `Set`, `Map` |
| **List / Set / Map** | เรียงลำดับได้ / ห้ามซ้ำ / จับคู่คีย์-ค่า | ไอเทมในกระเป๋า / ผู้เล่นออนไลน์ / ไอเทมตามรหัส |
| **`enum`** | ชุดค่าคงที่จำกัด | `enum Rarity { COMMON, RARE, EPIC }` |
| **`record`** | คลาสเก็บข้อมูลแบบสั้นและไม่เปลี่ยนค่า | `record DamageResult(double amount, boolean crit)` |
| **Lambda** | ฟังก์ชันสั้น ๆ ที่ส่งเป็นค่าได้ | `players.sort((a, b) -> a.level() - b.level())` |
| **Stream** | วิธีจัดการชุดข้อมูลแบบต่อท่อ | หาผู้เล่นที่เลือดต่ำสุดด้วย `min()` |
| **Exception (ข้อยกเว้น)** | เหตุการณ์ผิดปกติที่โปรแกรมต้องรับมือ | อ่านไฟล์ config ไม่ได้ |
| **try/catch** | ดักจับและรับมือกับ exception | ไม่ให้ปลั๊กอินล่มทั้งตัวเพราะไฟล์เสีย |
| **Stack trace** | ข้อความ error ที่บอกว่าพังที่ไฟล์/บรรทัดไหน | อ่านจากบนลงล่างเพื่อหาโค้ดของเรา |
| **JDK / JRE / JVM** | ชุดเครื่องมือ + ตัวรัน + เครื่องจักรเสมือนของ Java | JDK 25 ที่ติดตั้งไว้ใช้ทั้งคอมไพล์และรัน |
| **Bytecode** | โค้ดกลางที่ JVM อ่านได้หลังคอมไพล์ | `.class` ที่ซ่อนอยู่ใน `.jar` |
| **`.jar`** | ไฟล์แพ็กที่รวม `.class` หลายไฟล์ไว้ด้วยกัน | `EclipseCore-1.0.0.jar` |
| **Classpath** | รายการที่ Java จะไปหา class | ที่ทำให้ `java -jar` หาไดรเวอร์ฐานข้อมูลเจอ |
| **Package** | กลุ่มของคลาสที่จัดไว้ด้วยกัน | `com.mengkub.eclipse.core` |
| **Compile** | แปลงโค้ดที่มนุษย์เขียนให้เป็น bytecode | `./gradlew build` |
| **Unit test** | การทดสอบโค้ดชิ้นเล็กด้วยโค้ด | `DamageCalculatorTest` |
| **Refactor** | ปรับโครงสร้างโค้ดโดยไม่เปลี่ยนพฤติกรรม | แยกเมธอดยาวเป็น 4 เมธอด |
| **Debugger / Breakpoint** | เครื่องมือหยุดโปรแกรมเพื่อดูค่าจริง | หยุดตอนผู้เล่นใช้สกิลแล้วดูค่ามานา |
| **Dependency** | ไลบรารีที่โปรเจกต์ต้องใช้ | `paper-api`, `HikariCP` |

## 3. เครื่องมือ (Git / Gradle / IDE)

| คำ | ความหมายง่าย ๆ | ตัวอย่างในโปรเจกต์ |
| --- | --- | --- |
| **Git** | ระบบเก็บประวัติการแก้ไฟล์ | `git log` ดูว่าแก้อะไรเมื่อไร |
| **Repository (repo)** | โฟลเดอร์โปรเจกต์ที่ Git ติดตามอยู่ | `~/minecraft-mmo-dev/academy` |
| **Commit** | การบันทึกความเปลี่ยนแปลงพร้อมข้อความ | "เพิ่มสูตรคำนวณดาเมจพื้นฐาน" |
| **Branch** | สายการทำงานแยกออกมา | `feature/damage-calculator` |
| **Merge** | รวมสายงานกลับเข้าหากัน | รวม branch เข้า `main` |
| **Conflict** | แก้ไฟล์เดียวกันจน Git รวมให้ไม่ได้ | ต้องเลือกเองว่าเอาส่วนไหน |
| **Remote / origin** | repo ต้นทางบนอินเทอร์เน็ต | GitHub |
| **Pull Request (PR)** | ขอรวมโค้ดพร้อมให้คนอื่นรีวิว | ขอรวมงานตัวเองก่อน merge |
| **`.gitignore`** | รายการไฟล์ที่ไม่ต้องคอมมิต | `build/`, `*.jar`, ไฟล์ที่มีรหัสผ่าน |
| **Gradle** | เครื่องมือสร้าง/คอมไพล์โปรเจกต์ | `./gradlew build` |
| **Gradle Wrapper** | ตัวเรียก Gradle เวอร์ชันที่โปรเจกต์กำหนด | ไฟล์ `gradlew` ที่อยู่ในโปรเจกต์ |
| **Maven** | เครื่องมือ build อีกตัว (Paper แนะนำ Gradle) | มีไฟล์ `pom.xml` |
| **`build.gradle`** | ไฟล์บอกว่าคอมไพล์อย่างไร ใช้ไลบรารีอะไร | ที่ใส่ `paper-api` |
| **Artifact** | ไฟล์ผลลัพธ์จากการ build | `.jar` ใน `build/libs/` |
| **IDE / VS Code** | โปรแกรมช่วยเขียนโค้ด | ที่เราเขียน Java |

## 4. Minecraft / Paper

| คำ | ความหมายง่าย ๆ | ตัวอย่างในโปรเจกต์ |
| --- | --- | --- |
| **Vanilla** | Minecraft รุ่นเดิมที่ไม่ดัดแปลง | ไคลเอนต์ที่ผู้เล่นใช้เล่น |
| **Paper** | เซิร์ฟเวอร์ Minecraft รุ่นที่ใช้ API เขียนปลั๊กอินได้ และปรับประสิทธิภาพ | Paper 26.3 (build STABLE) |
| **Bukkit/Spigot API** | API ดั้งเดิมที่ Paper ต่อยอดมา | คำสั่งในตำราเก่ามักเป็น API นี้ |
| **Plugin (ปลั๊กอิน)** | โปรแกรมที่เติมความสามารถให้เซิร์ฟเวอร์ | `EclipseCore` ของเรา |
| **`plugin.yml`** | บัตรประชาชนของปลั๊กอิน (ชื่อ เวอร์ชัน คำสั่ง สิทธิ์) | ต้องมีทุกปลั๊กอิน |
| **`api-version`** | บอกว่าเขียนด้วย API รุ่นไหน | ถ้าไม่ใส่ อาจได้พฤติกรรมเก่าโดยไม่ตั้งใจ |
| **Lifecycle** | ช่วงชีวิตของปลั๊กอิน: โหลด → เปิด (`onEnable`) → ทำงาน → ปิด (`onDisable`) | จุดที่ต้องเตรียม/เก็บข้อมูล |
| **Event** | เหตุการณ์ในเกมที่เราดักฟังได้ | ผู้เล่นเข้าเกม, ตีมอน, ใช้ไอเทม |
| **Event Listener** | คลาสที่รับ event | `class PlayerJoinListener implements Listener` |
| **Event priority** | ลำดับที่ listener ถูกเรียก | ต้องทำงาน **หลัง** ปลั๊กอินอื่นยกเลิก event |
| **`ignoreCancelled`** | ตั้งว่าไม่ต้องรับ event ที่ถูกยกเลิกแล้ว | ป้องกันดาเมจซ้ำซ้อน |
| **Cancellable** | event ที่ยกเลิกได้ | ห้ามทำลายบล็อกในพื้นที่หวงห้าม |
| **Scheduler** | ตัวจัดคิวงานตามเวลา | งานทำซ้ำทุก 5 วินาที |
| **Main thread (main server thread)** | เธรดหลักที่ทำงานทีละอย่าง ใช้ทำเกม | ห้ามทำ DB query หนัก ๆ ที่นี่ |
| **Async (asynchronous)** | ทำงานคู่ขนานแยกจากเธรดหลัก | อ่าน/เขียนฐานข้อมูล |
| **Tick** | หน่วยเวลาของเกม 20 tick = 1 วินาที | TPS วัดว่า tick ทันไหม |
| **TPS** | tick ต่อวินาที (เต็ม 20) | ต่ำกว่า 19 = มีปัญหา |
| **Chunk** | พื้นที่โลกขนาด 16×16 บล็อก | การโหลด chunk เยอะทำให้หน่วง |
| **Entity** | สิ่งที่มีชีวิต/ขยับได้ (ผู้เล่น มอน สัตว์) | มอนเยอะเกินไปทำให้ TPS ตก |
| **`server.properties`** | ไฟล์ตั้งค่าเซิร์ฟเวอร์ | ตั้งพอร์ต เปิด/ปิด whitelist |
| **EULA** | ข้อตกลงการใช้งานของ Mojang ที่ต้องยอมรับตอนเปิดเซิร์ฟเวอร์ | ต้องตั้ง `eula=true` |
| **Whitelist** | รายชื่อผู้เล่นที่อนุญาตให้เข้า | ใช้ตอนทดสอบกับเพื่อน |
| **online-mode** | ตรวจบัญชีผ่านระบบ Mojang | ปิดในเซิร์ฟเวอร์ทดสอบเท่านั้น |
| **RCON** | ช่องควบคุมระยะไกล | ห้ามเปิดออกอินเทอร์เน็ต |
| **Adventure / Component** | ระบบข้อความสมัยใหม่ (สี คลิกได้) | ข้อความต้อนรับสวย ๆ |
| **Permission node** | ชื่อสิทธิ์ เช่น `eclipse.admin` | ตั้งผ่าน LuckPerms |
| **LuckPerms** | ปลั๊กอินจัดการสิทธิ์และกลุ่ม | กลุ่ม `default`, `vip`, `admin` |
| **GUI / Inventory menu** | เมนูในเกมที่สร้างด้วยกล่องเก็บของ | เมนูสกิล |
| **ItemStack** | ไอเทม 1 สแต็กในเกม | ไอเทมที่เราสร้างให้ผู้เล่น |
| **PersistentDataContainer (PDC)** | ที่เก็บข้อมูลถาวรบนไอเทม | รหัสไอเทมของเราเอง |
| **Custom Model Data** | ตัวเลขบนไอเทมเพื่อให้ resource pack แสดงโมเดลต่างกัน | ทำให้ดาบของเราหน้าตาต่างจากดาบเดิม |
| **Resource Pack** | ชุดไฟล์ที่เปลี่ยนหน้าตาเกม (เสียง ภาพ โมเดล) | pack ที่มีไอเทมของเรา |
| **`pack_format`** | เลขบอกว่า pack นี้ทำมาสำหรับไคลเอนต์เวอร์ชันไหน | ถ้าผิด จะไม่แสดงผล |
| **Texture / Model** | ภาพผิวและรูปทรง 3D | ทำใน Blockbench |
| **HUD** | องค์ประกอบบนหน้าจอ (เลือด มานา) | HUD ที่แสดงค่าสกิล |
| **Isometric camera** | มุมกล้องแบบ 45° แบบเกม RTS/Diablo | เป้าหมายที่ต้องทดลอง (ยังไม่ยืนยันว่าทำได้บน Vanilla) |

## 5. ข้อมูล ธุรกิจ และความปลอดภัย

| คำ | ความหมายง่าย ๆ | ตัวอย่างในโปรเจกต์ |
| --- | --- | --- |
| **Database (ฐานข้อมูล)** | ที่เก็บข้อมูลอย่างเป็นระบบ | เก็บเลเวล/เงิน/ไอเทมผู้เล่น |
| **SQL** | ภาษาที่ใช้คุยกับฐานข้อมูล | `SELECT level FROM players WHERE uuid = ?` |
| **Table / Row / Column** | ตาราง / แถว / คอลัมน์ | ตาราง `player_profile` |
| **Primary key** | คอลัมน์ที่ระบุแถวได้ไม่ซ้ำ | `uuid` ของผู้เล่น |
| **Index** | ดัชนีช่วยให้ค้นหาเร็วขึ้น | index ที่ `uuid` |
| **Query** | คำสั่งที่ส่งไปถามฐานข้อมูล | SELECT ข้อมูลผู้เล่น 1 คน |
| **JDBC** | ตัวเชื่อม Java กับฐานข้อมูล | ใช้ `getConnection()` |
| **PreparedStatement** | คำสั่ง SQL ที่ใส่ค่าแบบปลอดภัย | กัน SQL injection |
| **Connection pool** | สระการเชื่อมต่อที่ใช้ซ้ำ | HikariCP |
| **Transaction** | กลุ่มงานที่ต้องสำเร็จทั้งหมดหรือไม่ทำเลย | โอนเงิน: หักจาก A เพิ่มให้ B |
| **Migration** | การปรับโครงสร้างตารางเมื่อระบบอัปเดต | เพิ่มคอลัมน์ `mana` |
| **SQL injection** | การโจมตีผ่านข้อความที่ต่อเข้าไปในคำสั่ง SQL | กันด้วย PreparedStatement |
| **Backup / Restore** | สำรอง / กู้คืน | สำรอง `world/` + DB ทุกวัน |
| **Race condition** | ปัญหาที่เกิดเมื่อสองอย่างทำพร้อมกัน | กดซื้อไอเทมพร้อมกัน 2 ครั้งแล้วได้ของ 1 ชิ้นแต่หักเงินครั้งเดียว |
| **Dupe** | การทำให้ไอเทม/เงินงอกโดยไม่ควร | ปิดช่องทาง crash กลางการค้า |
| **Exploit** | การใช้ช่องโหว่เพื่อประโยชน์ตัวเอง | ใช้คำสั่งที่ไม่ควรเข้าถึง |
| **Anti-cheat** | ระบบตรวจจับการโกง | ตรวจความเร็วการเคลื่อนที่ (ทำได้จำกัด) |
| **DDoS** | การยิงคำขอจำนวนมหาศาลให้เซิร์ฟเวอร์ล่ม | ใช้ผู้ให้บริการที่มีการป้องกัน |
| **Uptime** | เปอร์เซ็นต์เวลาที่เซิร์ฟเวอร์ทำงานปกติ | เป้าหมาย 99% |
| **Retention** | อัตราที่ผู้เล่นกลับมาเล่นซ้ำ | วัดหลังเปิด Beta |
| **Conversion** | อัตราที่ผู้เล่นกลายเป็นผู้จ่ายเงิน | วัดจากผู้เล่นจริง |
| **Gross / Net** | รายได้รวม / รายได้หลังหักค่าธรรมเนียมและต้นทุน | ใช้คำนวณกำไรจริง |
| **Break-even** | จุดที่รายได้เท่าต้นทุนพอดี | คำนวณใน [business/operating-costs.md](business/operating-costs.md) |
| **PDPA / GDPR** | กฎหมายคุ้มครองข้อมูลส่วนบุคคล | เก็บข้อมูลผู้เล่นเท่าที่จำเป็น |
| **EULA / Commercial Guidelines** | ข้อกำหนดการใช้ Minecraft เชิงพาณิชย์ | ต้องอ่านก่อนเปิดขายของ |

## 6. คำที่ชอบสับสนกัน

| คำคู่ที่สับสน | ต่างกันอย่างไร |
| --- | --- |
| `>` vs `>>` | เขียนทับไฟล์ vs ต่อท้ายไฟล์ |
| `ArrayList` vs `HashSet` | ซ้ำได้+มีลำดับ vs ห้ามซ้ำ+ไม่มีลำดับ |
| `List` vs `Map` | เก็บเป็นลำดับ vs เก็บเป็นคู่คีย์-ค่า |
| `public` vs `private` | ใครก็เข้าถึงได้ vs เฉพาะในคลาส |
| `interface` vs `abstract class` | สัญญาล้วน vs มีโค้ดให้บางส่วน |
| compile ผ่าน vs ทำงานถูก | แปลภาษาได้ vs พฤติกรรมถูกต้อง (ต้องทดสอบ) |
| reload vs restart | โหลดปลั๊กอินใหม่เท่านั้น (เสี่ยงพัง) vs เริ่มใหม่ทั้งหมด (ปลอดภัย) |
| TPS vs MSPT | tick ต่อวินาที vs เวลาที่ใช้ต่อ tick (มิลลิวินาที) |
| กำไร vs รายได้ | เงินที่เหลือหลังหักต้นทุน vs เงินที่รับมา |
